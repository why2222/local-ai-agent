# 远程访问模式：默认关闭、强制令牌、精确域名匹配

2026-11-21 用户需要从 zconnect 反向代理（公网域名）访问应用。应用原有 Host 白名单（回环 + 私网 IPv4）按设计拒绝了该请求，用户明确要求增加正式的远程访问模式，并要求"项目默认不启用"。

决定：只有同时设置 `LOCAL_AI_REMOTE_HOST`（精确域名）和 `LOCAL_AI_REMOTE_TOKEN`（访问令牌）才启用，缺任一拒绝启动，杜绝无认证远程访问。登录链接 `/?token=...` 校验后设置 `HttpOnly; Secure; SameSite=Strict` Cookie 并 302 到无令牌地址；API 也接受 `?token=`。Origin 仅允许该域名的 https 同源。未配置时行为与之前完全一致。

用户已知情同意：流量经 zconnect 第三方（TLS 在其处终止、内容对其可见）；持令牌者可访问全部聊天文字、图片和模型管理接口。用途限于调试开发阶段。

## Considered Options

- **只放行域名、不加令牌**：实现最简单，但任何拿到链接的人都能读写聊天与模型配置，拒绝；令牌强制成对配置就是为此。
- **让反向代理改写 Host 绕过白名单**：首页可开但 API 的 https Origin 仍被拦，且同样无认证，拒绝；用户提出后改为实现本模式。
- **每次请求都带 `?token=`、不要 Cookie**：可行但令牌会留在浏览器历史与书签中，改为首次登录后 302 到无令牌地址并凭 Cookie 访问。

## Consequences

- 不允许"只放行域名不加令牌"的简化，这是防止误开无认证公网暴露的硬约束。
- 令牌通过环境变量提供，不写进 `config.json`、不进 git；启动日志不打印令牌。
- 回环与局域网访问不需要令牌，远程模式的校验只作用于配置的域名 Host。
