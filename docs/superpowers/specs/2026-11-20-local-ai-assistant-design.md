# 本地多模态 AI 助手设计

日期：2026-11-20

## 1. 目标

在当前 Linux 电脑上搭建一个本地网页 AI 助手，并保证应用代码和配置可以迁移到 Apple M2 MacBook。首次安装允许联网下载 Ollama 与模型；安装完成后，文字对话、图片理解和聊天历史均在用户设备上处理，不依赖云端 AI 服务。

当前设备为 6 核 Intel i3-N305、11 GiB 内存，无可用 NVIDIA 显卡。模型和上下文配置必须以该设备能够稳定运行为约束。

## 2. 首版范围

首版包含：

- 中文文字对话与流式回答
- JPG/PNG 图片上传、截图理解与中文 OCR
- 新建、切换和删除会话
- 停止生成与失败重试
- 文字历史与图片的本机持久化
- 模型、Ollama 和隐私状态提示
- Linux 安装运行说明及 M2 MacBook 迁移说明

首版不包含文档知识库、向量数据库、账号系统、语音、视频、公网访问、云端同步和多用户功能。文档问答作为后续独立阶段，不在首版提前实现。

## 3. 技术方案

采用 Ollama 与本地 Node.js 网页应用：

```text
浏览器
  ↓ 仅访问 127.0.0.1
本地 Node.js 服务
  ├─ 提供本地静态网页
  ├─ 管理会话与图片
  └─ 调用 127.0.0.1:11434 上的 Ollama
          ↓
    本地 Qwen3-VL 模型
```

Ollama 负责模型下载、加载、推理和 M2 上的 Metal 加速。Node.js 服务负责应用数据和模型调用，浏览器只负责交互。模型调用封装在独立模块中，未来可以替换为 llama.cpp，而不影响界面与历史记录格式。

应用使用 Node.js 内置模块和浏览器原生 HTML、CSS、JavaScript，不引入前端框架或外部 CDN。图标使用随应用提供的本地 SVG，字体使用系统字体栈。模型输出不得未经转义直接注入 `innerHTML`。

## 4. 模型选型与资源限制

默认模型固定为：

```text
qwen3-vl:2b-instruct-q4_K_M
```

该模型支持中文文字与图片输入，Ollama 模型文件约 1.9 GB。选择 Instruct 版本以获得更直接的日常回答，不使用响应更慢的 Thinking 版本作为默认。

默认运行参数：

- `num_ctx`：2048
- 单张图片最大：8 MiB
- 图片格式：JPEG、PNG，通过文件签名和 MIME 类型共同验证
- 同时生成请求数：1
- Ollama 地址：`http://127.0.0.1:11434`

模型文件大小不等于运行内存。安装后需要实测首字延迟、生成速度和峰值内存。如果出现内存耗尽，先减少上下文和关闭其他大型程序；仍无法稳定运行时，再选择更小的兼容模型。不得通过切换到云端模型解决本地资源不足。

模型虽然支持更长上下文，但首版不得按模型标称上限配置。文字历史按 2048 token 上下文预算裁剪；为避免重复处理图片，每次请求只携带当前或最近一张相关图片，追问更早图片时由用户重新添加。

迁移到 M2 后可以继续使用 2B 模型，也可以通过配置切换到 `qwen3-vl:4b-instruct-q4_K_M`。4B 模型不是首版验收的依赖。

## 5. 界面设计

最终采用 macOS 风格的 C 版雾紫灰设计：

- 浅色半透明侧栏、细分隔线、系统字体和克制圆角
- 雾紫灰主色，不使用大面积绿色或纯黑按钮
- 左侧为新建会话、历史列表和模型状态
- 中间为用户消息、图片附件和助手流式回答
- 底部为多行输入框、附件按钮和圆形发送按钮
- 新建会话按钮使用 macOS 式细腻渐变、高光、内边框和阴影
- 附件按钮使用系统次级按钮样式
- 按钮具有 hover、active、disabled 和 focus-visible 状态
- 输入框聚焦时显示低对比度焦点环
- 窄屏收起侧栏，保证输入区和消息区可用

预览图：`.superpowers/brainstorm/1892960-1795153447/content/ui-macos-c-refined.png`

预览中的红黄绿窗口按钮只用于表达 macOS 风格。正式网页不添加无实际功能的窗口控制按钮。

## 6. 组件边界

### 6.1 本地 HTTP 服务

只监听 `127.0.0.1`，提供静态文件、会话 API、图片 API 和健康检查。服务校验所有请求参数，拒绝路径穿越、非法文件和不支持的方法。不得监听 `0.0.0.0`，不得提供远程访问或公网隧道。

### 6.2 会话存储

每个会话独立保存，列表按更新时间排序。写入采用同目录临时文件加原子替换，避免中途退出损坏文件。删除会话时同时删除其图片。单个损坏会话应被隔离并提示，不能导致整个应用无法启动。

### 6.3 Ollama 客户端

只访问配置的本机 Ollama 地址，将文字和图片转换为 Ollama 聊天请求，并把流式输出转发给浏览器。浏览器中止请求时，同步中止上游生成并保存已产生的部分内容。

### 6.4 浏览器界面

负责会话导航、消息展示、图片预览、流式渲染和错误提示。所有静态资源均来自本地服务。用户选择图片后先在本机预览，不上传到任何外部服务。

## 7. 本地数据与配置

默认数据目录：

```text
data/
├── chats/
│   └── <chat-id>.json
└── images/
    └── <chat-id>/
        └── <image-id>.<jpg|png>
```

会话 JSON 包含：

- 会话 ID、标题、创建时间和更新时间
- 按顺序排列的消息
- 消息 ID、角色、文字、创建时间和完成状态
- 可选图片引用，不直接在 JSON 中重复存储图片 Base64

标题取自首条用户消息的有限长度文本。模型名称、上下文大小、端口和数据目录通过本地配置设置；网络监听地址固定为本机回环地址。

`data/`、本地日志和 `.superpowers/` 必须加入 `.gitignore`，防止聊天数据与设计临时文件被提交。

迁移到 M2 时复制应用代码、配置以及 `data/`；模型在 MacBook 上重新下载。不得把本机绝对路径写死在应用模块中。

## 8. 应用接口

接口只接受本机请求：

- `GET /api/health`：返回 Ollama 与默认模型可用状态
- `GET /api/chats`：返回会话摘要列表
- `POST /api/chats`：创建空会话
- `GET /api/chats/:id`：返回会话完整内容
- `DELETE /api/chats/:id`：删除会话及关联图片
- `POST /api/chats/:id/messages`：提交文字和可选图片引用，以流式方式返回回答
- `POST /api/chats/:id/images`：验证并保存图片
- `GET /api/chats/:id/images/:imageId`：读取本机会话图片

聊天请求在服务器内部维护单次生成锁。停止生成通过中止当前 HTTP 请求完成，不额外开放远程控制接口。

## 9. 异常处理

- Ollama 未运行：显示启动方法和重试入口。
- 默认模型未下载：显示精确的本地模型下载命令。
- 模型生成失败或超时：保留用户消息，允许重试，不自动切换模型。
- 内存不足：保留历史，提示减少上下文或关闭大型程序。
- 用户停止：保存部分回答并标记“已停止”。
- 图片超限或格式不支持：发送前拒绝并说明原因。
- 存储失败：不伪报保存成功，保留当前页面内容并显示错误。
- 日志只记录错误类型和必要上下文，不记录完整聊天正文或图片内容。

## 10. 隐私边界

唯一明确允许的外网操作是首次下载 Ollama、应用依赖和模型。正常运行阶段：

- 应用不调用任何云端 AI API
- 页面不加载外部字体、脚本、图片或统计服务
- Ollama 仅使用本地模型，不使用 `-cloud` 模型
- Node.js 和 Ollama 服务仅绑定本机回环地址
- 聊天文字和图片只写入本地数据目录
- 不创建局域网、公网隧道或远程端口转发

断网验收验证应用功能与资源请求，不代表对整个操作系统或其他软件的网络行为作保证。

## 11. 验证与完成标准

首版完成后必须实际执行：

1. 在当前 Linux 设备安装 Ollama 0.40.16 或兼容更新版本，并下载指定模型；0.12.7 已无法拉取当前模型清单。
2. 启动真实服务，通过浏览器完成中文提问、流式回答、停止和重试。
3. 上传真实中文截图，完成本机 OCR 与总结。
4. 重启应用，确认历史文字和图片可恢复；删除会话，确认对应文件被删除。
5. 连续完成至少 3 次文字问答和 1 次图片问答，无进程崩溃或内存耗尽。
6. 记录实测首字延迟、生成速度和内存占用，作为模型是否适合当前设备的依据。
7. 模型下载完成后断网，验证文字和图片对话仍可使用。
8. 检查网页无外部资源请求，应用与 Ollama 只监听 `127.0.0.1`。
9. 提供 M2 MacBook 的安装、迁移、Metal 加速和 4B 模型切换说明。

当前没有 M2 设备，因此 MacBook 部分只能交付可执行步骤和跨平台配置，不能标记为已完成真机验证。
